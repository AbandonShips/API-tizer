# API-Tizer

**현재 버전: v1.1**

하나의 질문을 ChatGPT · Claude · Gemini · Grok 그리고 로컬 LLM 여러 개에 **동시에** 보내고,
답을 나란히 비교하거나 **마스터 모델**이 하나로 요약해 주는 개인용 멀티 AI 콘솔입니다.

- 🔐 모든 데이터(키 · 대화 기록)는 **이 브라우저 안에만** 암호화(AES‑256‑GCM)되어 저장됩니다. (로컬 모드)
- ☁️ **온라인 동기화 모드**를 켜면 여러 기기에서 같은 데이터를 쓸 수 있습니다. 이때도 **영지식(Zero‑Knowledge)** 구조라 서버에는 **복호화 불가능한 암호문만** 올라갑니다.
- 🌐 지원 모델은 실시간 **웹 검색** 후 출처를 함께 표시합니다.
- 📊 모델별 추정 **토큰 · 비용**을 누적 집계합니다(수동 초기화).
- 📎 이미지 · 텍스트 · PDF **첨부**를 지원합니다.
- 📱 PC / 모바일 레이아웃을 자동·수동으로 전환합니다.

## 실행 방법 (PC)

1. 이 폴더에서 `start.bat` 을 실행합니다. (또는 터미널에서 `python server.py`)
2. 브라우저에서 **http://localhost:8753** 접속.
3. 처음이면 **회원가입** 으로 아이디·비밀번호를 만듭니다.
   - ⚠ 비밀번호를 잊으면 암호화된 데이터를 **복구할 수 없습니다.**
4. **⚙️ 설정** 에서 사용할 모델의 **API 키**를 입력하고 저장합니다.

> 코드를 수정한 뒤에는 브라우저에서 **Ctrl+Shift+R**(강력 새로고침) 한 번 해 주세요.

## 📱 휴대폰에서 접속하기

서버를 켜면 콘솔에 **이 PC 주소**와 **같은 와이파이용 주소**가 함께 표시됩니다.

```
이 PC:                   http://localhost:8753
같은 와이파이의 휴대폰:   http://192.168.x.x:8753
```

휴대폰을 **PC와 같은 와이파이**에 연결한 뒤 위 `192.168.x.x` 주소로 접속하면 됩니다.

### ⚠ 중요 — 일반 http 주소에서는 로그인이 막힙니다

브라우저 보안 정책상 **`localhost` 가 아닌 일반 `http://` 주소**에서는
암호화 기능(Web Crypto)이 비활성화되어 **로그인·암호화가 동작하지 않습니다.**
즉, 위의 `192.168.x.x` 주소로 휴대폰에서 접속하면 화면은 보이지만 로그인이 안 될 수 있습니다.

휴대폰에서 **제대로** 쓰려면 둘 중 하나가 필요합니다.

1. **HTTPS 터널 (권장)** — PC에서 터널을 띄우면 `https://...` 주소가 생기고, 그 주소로는 휴대폰에서도 정상 동작합니다.
   - [cloudflared](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/) 예시:
     ```
     cloudflared tunnel --url http://localhost:8753
     ```
     출력되는 `https://something.trycloudflare.com` 주소를 휴대폰에서 엽니다.
   - 또는 [ngrok](https://ngrok.com/): `ngrok http 8753`
2. **PC 브라우저의 모바일 보기** — Chrome 개발자도구(F12) → 기기 툴바(📱)로 휴대폰 화면을 그대로 미리볼 수 있습니다.

## ☁️ 온라인 동기화 (영지식 / Zero-Knowledge)

로그인 화면 상단에서 **온라인**과 **이 기기에 저장**을 고를 수 있습니다(기본값: 온라인). 온라인 모드는 PC·휴대폰 등 여러 기기에서 같은 계정으로 로그인해 대화·설정·API 키를 자동으로 맞춰줍니다.

### 동작 방식 (왜 안전한가)

- 비밀번호에서 **두 개의 키**를 만듭니다.
  - **Key A (데이터 키)** — 모든 내용을 AES‑256‑GCM으로 암호화/복호화. **절대 서버로 전송되지 않습니다.**
  - **Key B (인증 토큰)** — 로그인 인증에만 쓰이며, 서버는 이것조차 **해시(PBKDF2)** 로만 저장합니다.
- 서버에는 **암호문 덩어리(iv + ct)만** 저장됩니다. 서버가 통째로 유출돼도 내용은 읽을 수 없습니다. → 개발자가 사용자 데이터를 들여다볼 수 없으므로 유출 책임 노출이 최소화됩니다.
- **차분 동기화(Delta Sync)**: 각 기기는 마지막 동기화 시각을 기억하고, 그 이후 바뀐 항목만 주고받습니다. 휴대폰에서 매번 전체 기록을 내려받지 않습니다.

> ⚠️ 비밀번호를 잊으면 Key A를 복구할 수 없어 **서버의 데이터도 영구히 복호화 불가**합니다.

### 동기화 서버 준비 (1회)

동기화에는 암호문을 보관할 백엔드가 필요합니다. 무료로 쓸 수 있는 **Cloudflare Workers + D1** 백엔드 코드와 배포 방법이 [`worker/`](worker/) 폴더에 있습니다. 요약:

1. `worker/README.md` 의 안내대로 `wrangler` 로 D1을 만들고 스키마를 적용한 뒤 `wrangler deploy`.
2. 배포 후 나오는 주소(`https://api-tizer-sync.이름.workers.dev`)를 로그인 화면의 **동기화 서버 설정**에 입력합니다. (또는 `src/sync.js` 의 `DEFAULT_ENDPOINT` 에 고정)
  - 현재 저장소는 `https://api-tizer-sync.kangmin1152.workers.dev` 로 기본 연결되어 있습니다.
3. 커스텀 도메인을 쓰면 `index.html` 의 CSP `connect-src` 에 그 도메인을 추가하세요. 기본 `*.workers.dev` 주소는 이미 허용되어 있습니다.

### 사용

1. 로그인 화면에서 **온라인 동기화**를 선택하고 회원가입/로그인합니다.
2. PC에서 API 키와 대화를 만든 뒤, 휴대폰에서 같은 계정으로 로그인하면 자동으로 내려받습니다.
3. 사이드바 하단의 **⟳ 동기화** 버튼으로 즉시 동기화할 수 있고, 백그라운드에서도 주기적으로 동기화됩니다.

### 한계 (현재 버전)

- 충돌 해결은 "서버에 마지막으로 도달한 변경이 승리"하는 단순 방식입니다(개인용 다중 기기에 적합).
- 온라인 계정의 **비밀번호 변경/계정 삭제(서버 측)** 는 아직 앱에서 지원하지 않습니다.
- 네트워크가 없으면 이미 로그인한 기기에서는 로컬로 계속 쓰이며, 연결되면 다시 동기화됩니다.

## GitHub Pages 배포와 보안

이 앱은 서버가 없는 정적 웹앱이라 GitHub Pages에 배포할 수 있습니다. 단, 공개 URL로 서비스하더라도 데이터는 서버에 저장되지 않고 각 사용자의 브라우저 저장소에만 저장됩니다.

### 배포 순서

1. GitHub에서 새 public repository를 만듭니다.
2. 이 폴더에서 git을 초기화하고 원격 저장소를 연결합니다.
3. `main` 브랜치로 push합니다.
4. GitHub repository의 **Settings → Pages** 로 이동합니다.
5. **Build and deployment → Source** 를 `Deploy from a branch` 로 선택합니다.
6. Branch를 `main`, folder를 `/ (root)` 로 선택하고 저장합니다.
7. 표시되는 `https://...github.io/.../` 주소에서 접속을 확인합니다.

배포 대상 파일은 루트의 `index.html`, `styles.css`, `src/`, 이미지 파일, `.nojekyll`, `README.md` 입니다. Python 서버 파일은 로컬 실행용이며 GitHub Pages에서는 사용되지 않습니다. `worker/` 폴더는 온라인 동기화용 Cloudflare 백엔드 코드로, GitHub Pages가 아니라 Cloudflare에 별도로 배포합니다(자세한 내용은 [`worker/README.md`](worker/README.md)).

> [!NOTE]
> 모든 데이터(계정·설정·API 키·대화)는 각 브라우저 저장소에 암호화되어 저장됩니다. 제 GitHub Pages 주소로 접속해도 데이터가 서버에 따로 저장되지는 않습니다.

### 배포 전 체크리스트

- `apitizer-backup-*.json`, `.env`, 개인 키 파일이 폴더에 있어도 `.gitignore`에 걸리는지 확인하세요.
- 실제 API 키가 코드에 들어가지 않았는지 확인하세요. API 키는 앱 설정 화면에서 각 브라우저에 입력합니다.
- API 제공사 콘솔에서 사용량 한도/결제 한도를 설정하세요.
- 배포 후 처음 접속한 브라우저에서 회원가입하고, API 키 입력 후 테스트 질문을 한 번 보내보세요.
- 다른 브라우저나 PC로 옮길 때는 **보안 & 백업** 의 암호화 백업 내보내기/가져오기를 사용하세요.

- 저장소에는 API 키나 백업 파일을 올리지 마세요. `apitizer-backup-*.json`, `.env*`, `secrets/` 등은 `.gitignore`에 포함되어 있습니다.
- 이미 API 키가 커밋된 적이 있다면 삭제만으로는 부족합니다. 해당 키를 제공사 콘솔에서 폐기하고 새 키를 발급하세요.
- 새 계정과 비밀번호 변경은 8자 이상 비밀번호를 요구합니다. 가능하면 12자 이상의 문장형 비밀번호를 권장합니다.
- 자동 로그인은 보안상 제거했습니다. 비밀번호에서 파생한 암호화 키는 메모리에만 존재합니다.
- 같은 브라우저에서 로그인 실패가 반복되면 잠시 잠깁니다. 정적 사이트라 서버 차원의 IP 차단은 불가능하지만, 로컬 데이터에 대한 반복 입력 시도를 줄입니다.
- Content Security Policy가 기본 API 도메인(OpenAI, Anthropic, Gemini, xAI)과 localhost 로컬 모델 연결만 허용합니다. 다른 원격 호환 API를 쓰려면 `index.html`의 CSP `connect-src`에 해당 도메인을 추가해야 합니다.
- GitHub Pages 자체는 HTTPS라 Web Crypto 사용 조건을 만족합니다.

가족용으로 가장 안전한 운영 방식은 공개 repo 대신 private repo + GitHub Pages 접근 제어가 가능한 요금제/조직 설정, 또는 Cloudflare Pages/Netlify 같은 호스팅에 기본 인증(Access)을 붙이는 방식입니다. 공개 Pages로 운영한다면 API 키 제한/사용량 한도/키 정기 교체를 꼭 함께 설정하세요.
